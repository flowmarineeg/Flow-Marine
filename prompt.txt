CURRENT GOAL
----------------------------------------

The Capacity Engine is considered CORRECT.

The objective is NOT to redesign the Capacity Engine.

The objective is to redesign the Booking workflow so that it naturally produces cleaner and more consistent data for the Capacity Engine.

The current booking workflow is confusing because the user first selects a Voyage, while that Voyage already contains POL/POD information, then the user is asked again to manually select POL and POD.

This duplicates responsibility and creates poor UX.

----------------------------------------
NEW BOOKING WORKFLOW
----------------------------------------

Layer 2

Current:

Voyage
↓

POL

↓

POD

New workflow:

Round
↓

Voyage (filtered by selected Round)
↓

Automatically use the selected Voyage's POL and POD.

There will be NO separate POL selector.

There will be NO separate POD selector.

The selected Voyage becomes the single source of truth for:

- voyageId
- POL
- POD

The booking should still store voyageId exactly as today unless there is a strong architectural reason not to.
