F-01 — AUTHENTICATION FLOW (Sprint020 — httpOnly Cookie)
================================================================================

  USER                FRONTEND                    BACKEND               DATABASE
  ────                ────────                    ───────               ────────

  MOUNT:
                      AuthContext mounts
                      useRef guard (fires once)
                      GET /auth/me           ──►  auth middleware
                                                  reads req.cookies.token
                                             ──►  User.findOne (cache miss)
                                                  ◆ valid token + user?
                                                     YES → return safeUser
                                                     NO  → 401 (no redirect)
                      ◆ 200?
                        YES → setUser, setIsAuthenticated(true)
                              localStorage.setItem('user', JSON.stringify(u))
                        NO  → setIsAuthenticated(false), localStorage.removeItem('user')
                      setIsLoading(false)

  LOGIN:
  Enter email +  ──►  AuthContext.login()
  password            POST /auth/login       ──►  validateLogin (no normalizeEmail)
                                             ──►  authService.login(email, password)
                                             ──►  User.findOne({email: lower})
                                                  bcrypt.compare(password, hash)
                                                  ◆ match?
                                                     YES → signToken(userId)
                                                           res.cookie('token', token, {
                                                             httpOnly:true, secure:isProd,
                                                             sameSite:isProd?'none':'strict',
                                                             maxAge: 24h
                                                           })
                                                           return { user } only (no token in body)
                                                     NO  → 401 (toast shown, no redirect)
                      setUser(u)             ◄──
                      setIsAuthenticated(true)
                      localStorage.setItem('user')
                      router.replace('/dashboard')

  LOGOUT:
  Click Sign out ──►  ConfirmModal shown
  Confirm        ──►  AuthContext.logout()
                      POST /auth/logout      ──►  res.clearCookie('token', {...})
                      setUser(null)
                      setIsAuthenticated(false)
                      localStorage.removeItem('user')

  COOKIE SETTINGS:
    httpOnly: true               → not readable by JS (XSS protection)
    secure:   NODE_ENV=production → HTTPS only in production
    sameSite: production='none'  → allows cross-origin (VPS deployment)
             development='strict' → same-site only in dev
    maxAge:   24h

  TOKEN RESOLUTION ORDER (auth.js middleware):
    1. req.cookies.token (httpOnly cookie — primary)
    2. Authorization: Bearer <token> (fallback — API tools, Postman, curl)

  RATE LIMITING (auth routes only):
    POST /auth/login, /auth/forgot-password, /auth/reset-password
    20 requests per 15 minutes per IP
    No rate limiting anywhere else in the app

  PASSWORD RESET FLOW (unchanged):
    POST /auth/forgot-password → generate resetToken → send email via SMTP
    User clicks link → /reset-password?token=... (Suspense boundary)
    POST /auth/reset-password → hash new password → save

  INVITE FLOW (unchanged):
    Admin creates user → generates inviteToken → sends invite email
    User clicks link → /accept-invite?token=... (Suspense boundary)
    POST /users/accept-invite → set password, activate account

  401 INTERCEPTOR EXEMPTIONS (axios.js):
    /auth/login         → wrong credentials show toast, not redirect
    /auth/me            → expected 401 on login page (not logged in)
    /auth/forgot-password, /auth/reset-password → public flows
    All other 401s:     clear localStorage 'user' + window.location.href='/login'

F-02 — RBAC PERMISSION FLOW (Sprint020 — Cache Layer)
================================================================================

  Every protected API route:

  Request
    │
    ▼
  auth.js middleware
    │  1. Read req.cookies.token (or Authorization header)
    │  2. jwt.verify(token)
    │  3. cache.get('user:<userId>') — TTL 60s
    │     MISS → User.findOne + populate → cache.set('user:<userId>', user, 60s)
    │  {SuperAdmin (roleId.isSystem=true) → bypasses ALL permission checks below}
    ▼
  rbac('moduleName') middleware
    │  1. cache.get('perm:<roleId>:<moduleName>') — TTL 120s
    │     MISS → Permission.findOne({roleId, module}) → cache.set(key, perm, 120s)
    │  2. check permission.actions.hidden → 403 if true
    │  3. map HTTP method to action (GET→read, POST→create, PUT→update, DELETE→delete)
    │     or use actionOverride: rbac('bookings','import')
    │  4. check permission.actions[action] → 403 if false
    ▼
  Controller function

  CACHE INVALIDATION:
    User cache:       user.service.update/softDelete/acceptInvite → cache.del('user:<id>')
    Permission cache: permission.service.saveByRoleId → cache.delByPrefix('perm:<roleId>:')

  FRONTEND RBAC:
    PermissionContext.can(module, action) → boolean
    PermissionContext.isHidden(module) → boolean
    permissionsLoaded flag: true after /permissions/:roleId returns
    SuperAdmin fast-path: isSuperAdmin=true → can() always true, isHidden() always false
    GET /permissions/:roleId: NO rbac guard (self-service, Sprint019 fix)

  DASHBOARD EXCEPTION:
    Dashboard tab: checked by isSuperAdmin (roleId.isSystem) NOT can('dashboard','read')
    Sidebar: if (href==='/dashboard' && !isSuperAdmin) return null
    Dashboard page: enabled:isSuperAdmin on useQuery (API never called for non-admin)
    Layout: non-SuperAdmin on /dashboard → redirect to FALLBACK_NAV first allowed page

F-29 — IN-MEMORY CACHE FLOW (NEW Sprint020)
================================================================================

  FILE: backend/src/utils/cache.js
  CLASS: TtlCache (Map-based, pure Node.js, no external deps)
  INSTANCE: single shared module.exports = new TtlCache()

  API:
    cache.get(key)              → value | undefined (checks expiry on read)
    cache.set(key, val, ttlMs)  → void  (default TTL 60s)
    cache.del(key)              → void
    cache.delByPrefix(prefix)   → void  (deletes all keys starting with prefix)
    cache.flush()               → void
    cache.size()                → number

  ENTRIES:
    'user:<userId>'          TTL 60s   ← user + populated roleId
    'perm:<roleId>:<module>' TTL 120s  ← permission doc with actions object
    'dashboard:stats'        TTL 90s   ← full stats+charts+activity object

  INVALIDATION RULES:
    user cache:
      cache.del('user:<id>') called in:
        user.service.update()
        user.service.softDelete()
        user.service.acceptInvite()

    permission cache:
      cache.delByPrefix('perm:<roleId>:') called in:
        permission.service.saveByRoleId()
      (deletes all module entries for that role at once)

    dashboard cache:
      TTL expiry only — no manual invalidation
      New stats computed after 90s automatically

  PERFORMANCE IMPACT:
    Before: every request = 2-3 DB queries before business logic (User + Permission)
