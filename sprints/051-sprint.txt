# Sprint 051 (V2 S2) - Revenue cycle - implementation log
Status: IMPLEMENTED in the working tree, NOT committed. Plan: sprints/049-sprint.txt section 5.
Gate: flag v2Invoices (items, drafts) + flag accounting (issue, settle, notes, cancel of issued).
With both OFF nothing changes for V1 invoices.

DESIGN (modules/billing, V1 invoice code left in place)
 R1  BookingItem        derived pricing group = bill-to agent + voyage + container type + freight rate;
                        loadedQty = Final Loading bookings in the group (one booking = one container).
                        syncForVoyages() recomputes unlocked items; locked items (owned by a live invoice
                        line) are never edited. Bookings already on a legacy non-cancelled invoice are
                        excluded. Hooked (flag-gated, async, never throws) into booking create/update/
                        delete and the Final Loading import save.
 R2  Booking fields     billToPartyId, shipperSource, paymentTerm, collectAgentId - schema only; no UI yet.
                        Old bookings bill their agent (D10 default).
 R3  Invoice fields     v2, docKind (Invoice|CreditNote|DebitNote), parentInvoiceId, totalMinor/paidMinor/
                        creditedMinor, issuedAt/By, cancelledAt/By/Reason, reason, ledgerEntryId, fx
                        {rate, baseTotalMinor}. Legacy float totalAmount/paidAmount are kept in step so V1
                        lists still read. InvoiceLine collection: partial unique index
                        one_live_line_per_item {bookingItemId} where cancelled:false = the DB-level
                        "one invoice per item" guarantee (E11000 -> DUPLICATE_BILLING).
                        Lines are created with the DRAFT (not at issue), so a second draft cannot grab the
                        same item either. Invoice number is also assigned at draft creation (as V1).
 R4  Wizard             /invoices/new shows the 4-step wizard when v2Invoices is on (Party&scope, Items with
                        auto-select + summary card, Terms, Review -> Save as Draft / Create & Issue).
 R4  Issue              one transaction: claim Draft->Issued with a conditional update, lock fx rate,
                        post DR 1100 Agent Receivable / CR 4000 Freight Revenue, accrue commission.
                        Issued = read-only (INVOICE_LOCKED), even for invoices:override (D15 applied as
                        recommended - confirm).
 R5  NOT_FINAL_LOADED   items only exist for Final Loading bookings; zero-qty items are rejected.
 R6  Cancel             reverses the ledger entry, cancels lines, frees items. Refused while settlements /
                        credit notes / debit notes exist (INVOICE_HAS_SETTLEMENTS). Draft delete removes
                        lines and frees items; issued invoices cannot be hard-deleted (INVOICE_POSTED).
 R7  Commission         on issue, from the agent's active AgentAgreement (fixedPerContainer, fixedPerBooking,
                        percentOfRate in basis points); DR 5400 / CR 2000. Cancelling the invoice does NOT
                        cancel it.
 R8  Settlements        InvoiceSettlement (Cash). Over-payment guard is the filter of one atomic
                        findOneAndUpdate (paid + credited + amount <= total), so concurrent requests can't
                        both pass (SETTLEMENT_EXCEEDS_BALANCE) - this closes audit H3 for V2. Posts
                        DR bank (1010 company / 1020 cash / 1200 partner account tagged partnerId) /
                        CR 1100. Void = whole settlement, reversing entry. Legacy POST payments on a V2
                        invoice is refused (USE_SETTLEMENTS). 'Offset' kind is reserved for the netting
                        engine (Sprint 052).
 R9  Credit / debit     credit note reduces the parent's open balance (CREDIT_EXCEEDS_BALANCE if it would
                        go negative): DR 4000 / CR 1100. Debit note is its own receivable (DN-), can be
                        settled: DR 1100 / CR 4000. Numbers CN-/DN-.
 R10 Overdue            computed lazily on read (D16 recommended), persisted on the next write.
 R11 Frontend           wizard, InvoiceV2Panel (issue, delete draft, settle, void, credit/debit note,
                        cancel). New permission actions on invoices: issue, cancel, record (D7) with
                        columns in the permission matrix.
 V1 guards              V1 invoice create is refused while v2Invoices is on (V2_INVOICES_ACTIVE);
                        V1 update/override refused on a V2 invoice.
