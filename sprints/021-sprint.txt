  PHASE 1 - Service Route Legs Bug Fix
  Status: DONE
================================================================================

  BUG-001: Route legs load with empty dropdowns (country, city, port, terminal)
  Root cause (two bugs combined):
    1. React Query v5 silently removed the onSuccess callback from useQuery.
       The route data was fetched successfully but the onSuccess handler never
       fired, so the legs state was never populated from the loaded data.
    2. Backend returns populated objects ({ _id, name, code }) for countryId,
       cityId, portId, terminalId, agentId. The leg state must extract the _id
       from the object before storing it.

  File changed:
    frontend/src/modules/services/RouteEditor.jsx

  Change:
    - Removed onSuccess from useQuery (RQ v5 no longer supports it)
    - Destructured data as routeData from useQuery return value
    - Added useEffect watching routeData:
        useEffect(() => {
          if (routeData?.legs?.length >= 2) {
            setLegs(routeData.legs.map(l => ({
              _key:       l._id || Math.random().toString(36).slice(2),
              countryId:  (typeof l.countryId  === 'object' ? l.countryId?._id  : l.countryId)  || '',
              cityId:     (typeof l.cityId     === 'object' ? l.cityId?._id     : l.cityId)     || '',
              portId:     (typeof l.portId     === 'object' ? l.portId?._id     : l.portId)     || '',
              terminalId: (typeof l.terminalId === 'object' ? l.terminalId?._id : l.terminalId) || '',
              agentId:    (typeof l.agentId    === 'object' ? l.agentId?._id    : l.agentId)    || '',
            })));
          }
        }, [routeData]);
    - typeof === 'object' guard handles both populated object and plain string ID
    - Cascading dropdowns (city list depends on countryId, etc.) now correctly
      receive the resolved IDs and their dependent queries fire properly

  PHASE 4 - Booking Form New Cargo Fields
  Status: DONE

  BKG-001: Add containerNumber (required PK), vgm, dg/dgPercent, containerStatus
  Business need:
    Each booking represents one physical container. containerNumber is the unique
    physical identifier for that container and is used as the primary reference
    key for matching and updating bookings via import. Without it, the system
    cannot reliably identify which booking to update in Final Loading.

  Backend files changed:
    backend/src/modules/bookings/booking.model.js
    backend/src/modules/bookings/booking.validation.js

  New model fields:
    containerNumber  String    REQUIRED, uppercase, indexed — e.g. MSCU1234567
    vgm              Number    optional, min 0 — Verified Gross Mass in kg
    dg               Boolean   default false — Dangerous Goods flag
    dgPercent        Number    optional, 0–100 — DG percentage (only meaningful when dg=true)
    containerStatus  String    enum ['Full', 'Empty'], default null — container load state

  containerNumber design decisions:
    - required: true at model level — new bookings cannot be created without it
    - index: true at model level — needed for fast containerNumber lookups in import
    - enum on containerStatus strictly limits values to Full and Empty only;
      Mongoose rejects any other string at the DB level

  Validation changes:
    validateCreate: containerNumber -> notEmpty().withMessage('Container number is required')
    validateCreate: containerStatus -> isIn(['Full','Empty'])
    validateUpdate: containerNumber -> optional (cannot change PK after creation)
    validateUpdate: containerStatus -> isIn(['Full','Empty'])

  PHASE 5 - Booking Excel Import Overhaul
  Status: DONE
================================================================================

  BKG-002: Fix critical containerNumber→commodity bug + switch match key

  Critical bug fixed:
    In saveImport() insertMany path, the doc builder had:
      commodity: r.containerNumber || null
    This was storing the container number in the commodity field and leaving
    containerNumber null on every imported booking. Bug existed since the field
    was first introduced. Fixed to:
      commodity:       r.commodity       || null
      containerNumber: r.containerNumber (always set — required field)

  Primary match key change:
    BEFORE: import matched existing bookings by bookingNumber
    AFTER:  import matches existing bookings by containerNumber + voyageId

    Rationale: containerNumber is the physical identifier of the container.
    bookingNumber is a system-generated reference number that may not even
    be known at import time. Using containerNumber means:
      - Booking mode: flags duplicate if same containerNumber already exists
        on this voyage (prevents double-booking the same box)
      - Final Loading mode: finds the existing booking for this container
        to update it to Final Loading status
      - Final Loading reconciliation: cancels bookings on this voyage
        whose containerNumber is NOT present in the manifest

================================================================================
  KEY DECISIONS & RULES ESTABLISHED IN THIS SPRINT
================================================================================

  1. containerNumber is the primary physical identifier for a booking.
     It is REQUIRED on create, indexed on the model, and used as the sole
     match key for both booking dedup and Final Loading reconciliation.
     bookingNumber remains the system-generated display reference but is
     NOT the match key for import operations.

  2. containerStatus is strictly Full or Empty — no other values accepted
     at model level (Mongoose enum) or API level (express-validator isIn).
     The previous free-text field has been locked down.

  3. React Query v5 has NO onSuccess on useQuery. Any existing code using
     onSuccess must be migrated to useEffect watching the query data.
     This is a permanent rule for all future RQ usage in this project.

  4. dgPercent must be nulled when dg=false. The server never stores a DG
     percentage for a non-DG shipment. Frontend clears it on toggle-off;
     backend import service sets dgPercent: dgFlag ? parseNum(...) : null.

  5. Audit log ValueDisplay must never use JSON.stringify. All values are
     rendered via the renderValue() function which produces human-readable
     plain text for all types. This is now the standard for any future
     before/after display.

  6. Toaster containerStyle zIndex must always exceed Modal zIndex.
     Modal is at 9999; Toaster containerStyle is set to 99999 globally
     in Providers.jsx. Never hardcode a lower value in individual toast calls.
