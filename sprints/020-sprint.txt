  PHASE 1 - Critical Security and Startup Fixes
  Estimate: 5h
================================================================================

  TASK 1.1 - Fix server startup order (ARCH-001)
  File: backend/src/server.js
  Problem:
    connectDB() is not awaited before app.listen(). Server accepts
    requests while Mongo may still be connecting or about to fail.
  Change:
    - Wrap entire startup in async IIFE:
        (async () => {
          await connectDB();
          // NOTE: seed() is NOT called here per owner note #1
          app.listen(PORT, () => logger.info(...));
        })();
    - Remove the unused `const seed = require('./config/seed')` import
    - Add SIGTERM + SIGINT graceful shutdown handlers

  TASK 1.2 - Authenticated file serving for uploads (SEC-001)
  Problem:
    express.static('/uploads') serves all expense receipts publicly with
    zero authentication. Anyone who knows the filename can download it.
  Files changed:
    - backend/src/server.js                          remove static middleware
    - backend/src/modules/expenses/expense.routes.js add GET /:id/attachment
    - backend/src/modules/expenses/expense.controller.js add getAttachment
    - backend/src/modules/expenses/expense.service.js   add getAttachmentPath
  Change:
    - Remove: app.use('/uploads', express.static('src/uploads'))
    - New route: GET /api/v1/expenses/:id/attachment
        . auth middleware required (must be logged in)
        . rbac('expenses') - must have read permission on expenses
        . Load expense record, verify not deleted
        . Verify file exists on disk
        . Stream file via res.sendFile(absolutePath)
        . Set Content-Disposition header so browser names file correctly

  TASK 1.3 - Sharp image compression for uploads (Owner note #4)
  File: backend/src/middleware/upload.js
  Dependency: add sharp to backend/package.json
  Problem:
    No image optimization. Large JPEGs/PNGs stored as-is. Can bloat storage
    and slow down serving.
  Change:
    - Keep multer diskStorage unchanged for destination and filename logic
    - Export new compressUpload middleware that wraps multer:
        1. Run multer (save raw file to disk)
        2. If mimetype is image/jpeg or image/png, run Sharp:
             - Resize to max 1920px width, preserve aspect ratio, no upscale
             - JPEG: quality 80, progressive: true
             - PNG: compressionLevel 8
             - Overwrite same file path
        3. If mimetype is application/pdf: skip Sharp, pass through unchanged
        4. Update req.file.size to compressed size
    - Replace uploadExpense export with compressUpload
    - Update expense.routes.js to use compressUpload instead of uploadExpense

  PHASE 2 - Auth Hardening: JWT Cookies + Rate Limiting
  Estimate: 10h
================================================================================

  Context:
    Current: login returns { token, user } and client stores token in localStorage
    Target:  login sets httpOnly cookie, client only tracks user in state/localStorage
    Owner note #2: secure=true only in production, SameSite=strict in dev / none in prod
    Owner note #3: rate limit applies to auth routes only

  TASK 2.1 - Switch JWT to httpOnly cookie (SEC-002, SEC-003)
  New dependencies: cookie-parser
  Files changed:
    - backend/package.json                      add cookie-parser
    - backend/src/server.js                     add cookie-parser middleware
    - backend/src/modules/auth/auth.controller.js  set/clear cookie on login/logout
    - frontend/src/config/axios.js              add withCredentials, remove token interceptor
    - frontend/src/context/AuthContext.jsx      cookie-based flow, /auth/me rehydration

  Backend changes:
    a) Install cookie-parser
    b) server.js: app.use(require('cookie-parser')()) after body parsers
    c) auth.controller.js login():
         const isProd = process.env.NODE_ENV === 'production';
         res.cookie('token', token, {
           httpOnly: true,
           secure:   isProd,
           sameSite: isProd ? 'none' : 'strict',
           maxAge:   24 * 60 * 60 * 1000,
         });
         return success(res, { user: safeUser(user) }, 'Login successful');
         // token NOT returned in body anymore
    d) auth.middleware.js: read token from req.cookies.token as fallback
         if not in Authorization header (supports both Bearer header and cookie)
    e) auth.controller.js logout():
         res.clearCookie('token', { httpOnly:true, secure:isProd, sameSite:isProd?'none':'strict' })
         return success(res, null, 'Logged out successfully')

  Frontend changes:
    a) axios.js:
         - Add withCredentials: true to axios.create() config
         - Remove request interceptor that reads localStorage token
           (browser sends httpOnly cookie automatically)
         - Keep 401 response interceptor (redirect on session expiry)
    b) AuthContext.jsx:
         - login(): response now only has { user }, no token
           Store user in state only (no token to store)
           Remove localStorage.setItem('token', t)
         - logout(): server clears cookie, just clear local user state
           Remove localStorage.removeItem('token')
         - Rehydration on mount: replace localStorage token check with:
             call GET /auth/me
             if 200 -> set user + isAuthenticated=true
             if 401 -> set isAuthenticated=false, isLoading=false
           This is the correct persistent-login pattern with httpOnly cookies
         - Keep localStorage for user object only (name, role for display)

  TASK 2.2 - Auth-only rate limiting (SEC-004, Owner note #3)
  New dependencies: express-rate-limit
  Files changed:
    - backend/package.json             add express-rate-limit
    - backend/src/modules/auth/auth.routes.js  add limiter to 3 routes only

  Change:
    - Install express-rate-limit
    - Define limiter locally in auth.routes.js (NOT globally):
        const { rateLimit } = require('express-rate-limit');
        const authLimiter = rateLimit({
          windowMs: 15 * 60 * 1000,
          max: 20,
          message: { success: false, message: 'Too many attempts, please try again later' },
          standardHeaders: true,
          legacyHeaders: false,
        });
    - Apply to ONLY these three routes:
        POST /login
        POST /forgot-password
        POST /reset-password
    - No global rate limiting anywhere else per owner note #3

  PHASE 3 - Backend Performance
  Estimate: 10h
================================================================================

  TASK 3.1 - In-memory cache for user and permission lookups (PERF-001, PERF-002)
  File: backend/src/utils/cache.js (NEW)
  Problem:
    Every request does User.findOne + Permission.findOne = 2-3 DB queries
    before any business logic runs. At scale this is the primary bottleneck.
  Change:
    - Create simple Map-based TTL cache: get(key), set(key,val,ttlMs), del(key), delByPrefix(prefix)
    - No external dependency, pure Node.js
    - auth.js middleware: cache user by userId, TTL 60s
        cache key: user:<userId>
        miss: fetch from DB, cache result
        invalidate: call cache.del('user:<id>') in user.service update/delete
    - rbac.js middleware: cache permission by roleId+module, TTL 120s
        cache key: perm:<roleId>:<module>
        miss: fetch from DB, cache result
        invalidate: call cache.delByPrefix('perm:<roleId>') in permission.service save

  TASK 3.2 - Audit logger fire-and-forget (PERF-003)
  File: backend/src/middleware/auditLogger.js
  Problem:
    res.json is overridden as async, awaiting AuditLog.create before sending
    response. Every mutation is delayed by the audit write latency.
  Change:
    - Remove async override of res.json
    - Use res.on('finish') event instead:
        next() is called, response flows normally
        after response finishes, setImmediate fires AuditLog.create
        if AuditLog.create fails, log error only - never block response

  TASK 3.3 - Response compression (PERF-010)
  Files: backend/src/server.js, backend/package.json
  Change:
    - Install: compression
    - app.use(require('compression')()) after helmet, before routes
    - Significant win for JSON list and report payloads

  TASK 3.4 - DB connection options (PERF-009)
  File: backend/src/config/db.js
  Change:
    mongoose.connect(MONGODB_URI, {
      serverSelectionTimeoutMS: 5000,
      socketTimeoutMS: 45000,
      maxPoolSize: 10,
      minPoolSize: 2,
    })

  TASK 3.5 - AppError class to unify error conventions (ARCH-002)
  File: backend/src/utils/AppError.js (NEW)
  Problem:
    Services throw { status, message } but errorHandler reads err.statusCode.
    Controllers catch and manually forward err.status. If any controller
    forgets to catch, a service error becomes a generic 500.
  Change:
    - class AppError extends Error { constructor(statusCode, message) }
    - Update ALL 22 service files to throw new AppError(400, 'msg')
    - errorHandler already reads err.statusCode - alignment complete

  TASK 3.6 - Trust proxy + graceful shutdown (ARCH-001 remainder)
  File: backend/src/server.js
  Change:
    - app.set('trust proxy', 1) - correct req.ip behind VPS nginx
    - SIGTERM/SIGINT handler: close server + mongoose.disconnect()
