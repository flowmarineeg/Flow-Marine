## Hard rules (never break)
**Ledger / money (V2)**
- Write to the ledger ONLY via `LedgerService.post/reverse`. Never edit/delete JournalEntry/JournalEntryLine via a model (append-only; models throw `LEDGER_IMMUTABLE`).
- Never remove `lockAgent()` (agent cash paths), `assertRoundOpenTx` (inside `LedgerService.post`), or the unique partial indexes (`one_live_line_per_item`, `reversesEntryId`, `pdaExpenseId`).
- New money fields = integer minor units (`utils/money.js`, backend + frontend). No floats. `allocate()` is largest-remainder.
- Every new mutating service MUST call the `roundLock` pre-check (409 `ROUND_CLOSED`).
- Issued invoices are locked; corrections = credit/debit notes. Posted expenses are frozen; reverse first.
- Deletes: `utils/dependents.js` (`assertNoDependents`, `HAS_DEPENDENTS`), no cascades (only exception: deleting a Round deletes its own voyages). Add an entry whenever a new collection references an existing one. Ledger-referenced records are never hard-deleted.
- No feature flags exist; `Round.v2` is true for all new Rounds.

**Capacity & bookings**
- DO NOT touch `teuResolver.js`, `voyageGenerator.js` for V2 work (rule R10). **`capacity.service.js` was rewritten per leg on 2026-11-10 by owner decision** (FL-01 fixed): keep it per segment (`capacityLegs.logic.js`), both layers counted, never reintroduce the voyage-chain carry. Any service mutating bookings/voyages/rounds must call `invalidateRoundCache(roundId)`.
- **Booking `voyageId` is always found by the server** (`voyageMatch.logic.js`: a live voyage of the round whose `portCalls` visit POL then POD); the client never forces it (`voyageId` is only a pick among the candidates of a 409 `VOYAGE_AMBIGUOUS`). `polId/podId` are the **booking's own ports** (any ports of the run), chosen by the user / read from the Excel row, validated against the run, immutable (changed 2026-11-10; they used to be copied from the voyage). `containerNumber` is the import match key. Import scope = (Round + Agent); the import re-analyses the raw rows on save and never trusts the preview echo. Discharge import/list scope = Round + Agent + POD [+ POL, Voyage].
- **Partner users** (`Role.isPartnerRole` + `User.partnerId`): `rbac`/`hasPermission` refuse every module except `bookings` for them; booking services confine them to their own partner (`partnerScope.js`). `Booking/ManualBooking.partnerId` is a reference label only (no money effect). `DEPENDENTS.partner` covers bookings and partner users.
- `totalFreight` is computed server-side. `Booking.dischargeStatus` is independent of `status`.
- Voyage display: `getVoyageLabel(v)` (name, fallback to number). `voyageDisplayOrder.js` re-sort is rendering-only; never write `Voyage.sequence`.
- Revenue = Layer 2 Booking, status `Final Loading` only (reports, dashboard). Layer 1 = ManualBooking (counts toward capacity unless Cancelled).

**Platform**
- Response shape `{success, data, message, pagination?}`. Errors: `AppError(status, message, code)`.
- RBAC middleware on every protected route; audit logger stays fire-and-forget (`res.on('finish')` + `setImmediate`); TrackingHistory append-only; AuditLog read-only.
- Cookie auth only (no localStorage token). No `.normalizeEmail()`. Dashboard is SuperAdmin by role identity (`user.roleId.isSystem`), not permissions.
- Mongo: `$unwind` always `preserveNullAndEmptyArrays: true`. No duplicate indexes (inline `unique:true` only). Escape user input in `$regex` with `utils/escapeRegex.js`. Validate string types on token fields (NoSQL injection).
- `buildZipStream` (not `exportZip`); `compressUpload` (not `uploadExpense`); `seed.js` never auto-runs from the server.
- Frontend: imports via `@/`; `useSearchParams` pages need `<Suspense>`; async `params` via `use(params)`; Modal uses `createPortal`; layout uses `overflow:clip`; per-page tables need `min-w-0` + `overflow-x-auto`; Chart.js targeted registration only; reports use `refetch()` with `enabled:false`; required fields get one red `*`, optional none; mutation errors via `showErrorToast()`.
- Master data: accounts on Services / Expense types / Customers are chosen by type + code prefix (`ledger/accountRules.js`), never by 6-digit group; `ContainerType.teuFactor` is informational — capacity still uses `teuResolver` (R10); any agent or customer can handle bookings (agent roles/partyType removed from the form and API 2026-10-27); expense type `operationalLevel` constrains expense scope; vessel shares lock after the first accounting entry.
- Permission `override` toggle: only `voyages:override` is consulted (`voyage.controller.js#update`). Other modules: no-op.

## Architecture map
- Backend `src/modules/<name>/{model,service,controller,routes,validation}`; middleware `auth, rbac (+hasPermission), csrf, auditLogger, upload, errorHandler`; utils `cache (TTL), AppError, autoNumber, money, dependents, moneyAudit, pickFields, escapeRegex, teuResolver, voyageGenerator`.
- V2 modules: `accounting` (Masters → Accounting, chart UI), `invoiceServices` (`/invoice-services`), `ledger, partners, agreements, billing (routes at /invoices), agentAccounts (/agent-accounts), partnerSettlement (/round-accounting), rounds/roundLock.js`. Master-data module added 2026-10-25: `customers` (`/customers`, perm `customers`). Pure-logic files with unit tests: `vessel.logic`, `expenseType.logic`, `agent.logic`, `customer.logic`, `utils/masterValidators.js`.
- Cache TTLs: user 60s, permissions 120s, capacity 60s, dashboard 90s.
- Auto-numbers: R000001, BK-, MB-, INV-, CN-, DN-, HC-, JE-. Voyage = `V` + global 4-digit counter + direction letter (`V0001E`, `V0002W`, N, S) since 2026-11-08.
- Status flows — Round: Planned→Active→Completed | →Cancelled (from Planned/Active). Voyage: Scheduled→Departed→In Transit→Arrived→Completed; Scheduled/Departed/In Transit→Cancelled (**Arrived cannot be Cancelled**; bypass all with `voyages:override`). Booking: Pending→Confirmed→Final Loading; any non-final→Cancelled (the map lists Final Loading→Cancelled, but Final Loading/Cancelled bookings are not editable, so that move is only reachable through the Final Loading import — audit FL-05).
- Round financial axis (independent): `closeStatus` Open→ReadyToClose→Closed, reopen with reason.
